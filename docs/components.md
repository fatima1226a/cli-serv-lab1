Описание компонентов системы

1. Клиентский уровень

React SPA (Frontend)

Frontend — пользовательский интерфейс приложения, разработанный на React. Он отображает каталог фильмов, информацию о фильмах, историю просмотров, оценки и персональные рекомендации.

Основные функции:

- Отображение каталога фильмов и подробной информации о них.
- Отправка запросов на сервер через REST API.
- Отображение результатов, полученных от сервера.
- Отправка оценок фильмов и данных о просмотре.
- Отображение истории просмотров и рекомендаций.

Пользователь (Viewer)

Пользователь взаимодействует с приложением через браузер. Он может просматривать каталог фильмов, ставить оценки, сохранять историю просмотров и получать персональные рекомендации.

Менеджер контента (Content Manager)

Менеджер контента отвечает за управление каталогом фильмов. В зависимости от назначенных прав он может добавлять новые фильмы, редактировать информацию о фильмах и управлять их доступностью.

2. Серверный уровень (Backend)

Серверная часть приложения разработана с использованием NestJS. Она обрабатывает запросы от клиента, выполняет бизнес-логику и организует взаимодействие с базой данных.

Controller

Controller принимает HTTP-запросы от frontend через REST API. Он проверяет параметры запроса на соответствие установленным правилам и передаёт обработку соответствующему сервису.

После выполнения операции Controller формирует HTTP-ответ и отправляет его клиенту в формате JSON.

Service

Service содержит бизнес-логику приложения. Он обрабатывает операции, связанные с фильмами, оценками, историей просмотров и рекомендациями.

Service взаимодействует с ORM для получения, добавления, изменения и удаления данных. Например, при выставлении оценки он проверяет и организует сохранение оценки пользователя, а при запросе рекомендаций получает необходимые данные для формирования списка фильмов.

Auth + Guards / RBAC

Компонент отвечает за аутентификацию пользователей и разграничение доступа к функциям системы.

Аутентификация позволяет определить, кто выполняет запрос. Guards проверяют, разрешено ли пользователю выполнять запрашиваемую операцию. RBAC (Role-Based Access Control) предоставляет права в зависимости от роли пользователя.

В системе предусмотрены две основные роли:

- Viewer — просмотр каталога, выставление оценок, сохранение истории просмотров и получение рекомендаций.
- Content Manager — управление каталогом фильмов в соответствии с назначенными правами.

Модули приложения

Backend разделён на функциональные модули, каждый из которых отвечает за определённую область системы.

- Movies — получение каталога фильмов, просмотр подробной информации, добавление и редактирование фильмов.
- Tracking — сохранение истории просмотров, времени просмотра и процента досмотра.
- Ratings — добавление и изменение пользовательских оценок фильмов.
- Recommendations — формирование персональных рекомендаций на основе доступных данных о предпочтениях и просмотрах пользователя.

Такое разделение упрощает поддержку и дальнейшее расширение приложения.

ORM

ORM (Object-Relational Mapping) обеспечивает взаимодействие серверной части с реляционной базой данных через объекты и модели приложения.

ORM преобразует операции приложения в SQL-запросы и возвращает результаты их выполнения. Это позволяет работать с данными пользователей, фильмов, жанров, оценок и просмотров без необходимости вручную формировать каждый SQL-запрос.

3. Уровень данных

PostgreSQL

PostgreSQL — реляционная база данных, предназначенная для постоянного хранения информации приложения.

В базе данных хранятся:

- пользователи и их роли;
- фильмы и жанры;
- связи между фильмами и жанрами;
- пользовательские оценки фильмов;
- история просмотров и процент досмотра;
- данные о сформированных рекомендациях, если они сохраняются системой.

Связи между таблицами обеспечивают целостность данных и позволяют получать информацию из нескольких связанных сущностей.

4. Взаимодействие компонентов

Основной сценарий работы приложения выглядит следующим образом:

1. Пользователь выполняет действие в интерфейсе React SPA.
2. Frontend отправляет HTTP-запрос к backend через REST API в формате JSON по HTTPS.
3. Controller принимает запрос и передаёт его соответствующему сервису.
4. Auth и Guards проверяют личность пользователя и его права доступа в тех операциях, где это необходимо.
5. Service выполняет бизнес-логику и обращается к ORM для работы с данными.
6. ORM выполняет необходимые SQL-операции с PostgreSQL.
7. Полученные данные передаются обратно через Service и Controller.
8. Frontend получает HTTP-ответ и обновляет интерфейс.

Клиент взаимодействует с базой данных только через серверную часть. Прямой доступ frontend к PostgreSQL не предусмотрен.


Сущности базы данных

1. User — пользователь системы: идентификатор, имя, электронная почта, пароль в хешированном виде и роль.
2. Movie — фильм: идентификатор, название, описание, год выпуска и продолжительность.
3. Genre — жанр фильма: идентификатор и название.
4. MovieGenre — связь между фильмами и жанрами.
5. Rating — оценка фильма пользователем.
6. ViewingHistory — история просмотров пользователя, включая время просмотра и процент досмотра.
7. Recommendation — рекомендация фильма конкретному пользователю.

Связи между сущностями

- User → Rating: один пользователь может оставить оценки многим фильмам.
- Movie → Rating: один фильм может иметь оценки от многих пользователей.
- User → ViewingHistory: у пользователя может быть много записей о просмотрах.
- Movie → ViewingHistory: один фильм может встречаться во многих записях истории просмотров.
- Movie ↔ Genre: связь многие-ко-многим реализуется через MovieGenre.
- User → Recommendation: одному пользователю может соответствовать множество рекомендаций.
- Movie → Recommendation: один фильм может быть рекомендован разным пользователям.
