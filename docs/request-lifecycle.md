Жизненный цикл запроса

Сценарий: пользователь выставляет оценку фильму

Пользователь открывает страницу фильма, выбирает оценку и нажимает кнопку сохранения. Система проверяет запрос, сохраняет оценку в базе данных и возвращает результат операции.

1. Действие пользователя

Пользователь выбирает оценку фильма в интерфейсе React SPA и нажимает кнопку сохранения.

Frontend формирует HTTP-запрос, содержащий идентификатор фильма и выбранную оценку. Запрос отправляется на сервер по HTTPS через REST API в формате JSON.

2. Получение запроса Controller

Controller принимает запрос от frontend. Он проверяет корректность структуры и параметров запроса, например наличие идентификатора фильма и допустимость значения оценки.

Если запрос содержит некорректные данные, сервер возвращает ошибку валидации. В противном случае запрос передаётся сервису для дальнейшей обработки.

3. Проверка аутентификации и прав доступа

Система проверяет, авторизован ли пользователь и имеет ли он право выставлять оценки.

Если пользователь не вошёл в систему или не имеет необходимых прав, операция отклоняется. Идентификатор пользователя определяется на основе проверенных данных аутентификации, а не доверяется произвольному значению из запроса клиента.

4. Обработка Service

Service выполняет бизнес-логику операции. Он проверяет существование фильма и определяет, необходимо ли создать новую оценку или обновить уже существующую.

Один пользователь может иметь только одну актуальную оценку для одного фильма. При повторной отправке оценки существующая запись обновляется.

5. Взаимодействие с ORM и базой данных

Service обращается к ORM, который выполняет необходимые операции с PostgreSQL.

В базе данных создаётся новая запись об оценке либо обновляется существующая. Запись связывает пользователя с фильмом и содержит выставленную оценку.

Операция выполняется с учётом ограничений базы данных, обеспечивающих корректность и целостность данных.

6. Формирование ответа сервера

После успешного сохранения Service возвращает результат Controller.

Controller формирует HTTP-ответ с информацией об успешной операции и сохранённой оценке. Ответ передаётся frontend в формате JSON.

Если при обработке произошла ошибка, сервер возвращает соответствующий HTTP-статус и сообщение об ошибке.

7. Обновление интерфейса

React SPA получает ответ сервера.

Если оценка успешно сохранена, интерфейс отображает обновлённое значение и сообщает пользователю об успешном выполнении операции. Если произошла ошибка, интерфейс показывает соответствующее сообщение.

Обработка ошибок

Система должна учитывать следующие ситуации:

- Некорректная оценка: сервер возвращает ошибку валидации.
- Пользователь не авторизован: запрос отклоняется с HTTP-статусом 401.
- Недостаточно прав: сервер возвращает HTTP-статус 403.
- Фильм не найден: сервер возвращает HTTP-статус 404.
- Ошибка базы данных: сервер фиксирует ошибку в журнале и возвращает безопасное сообщение об ошибке без раскрытия внутренних данных.

Итог

Жизненный цикл запроса демонстрирует взаимодействие клиентского, серверного и информационного уровней. Frontend отвечает за взаимодействие с пользователем, Controller принимает и направляет запросы, Service выполняет бизнес-логику, Auth и Guards контролируют доступ, ORM обеспечивает работу с PostgreSQL, а база данных хранит результат операции.
